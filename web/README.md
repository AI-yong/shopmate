# web/ — SHOPMATE 프런트엔드

빌드 없이 도는 순수 프런트엔드(ES 모듈)입니다. `src/shopmate/server.py` 가 화면과 `/api/*` 를
같은 포트에서 냅니다. 목업 데이터만으로도 화면을 볼 수 있습니다.

## 띄우기

실서버와 함께 (기본):

```bash
python -m shopmate.server     # 프로젝트 루트에서 (pip install -e . 뒤)
# http://127.0.0.1:8000
```

포트를 나누면 CORS 를 설정해야 하는데 이 프로젝트에서 배울 것이 없는 작업이라
한 서버로 묶었습니다. `/api/chat` 은 로컬 모델 서버가, 사진은 MinIO 가 떠 있어야
동작합니다 (`.env` 참고). 사진을 못 불러오면 SVG 그림이 대신 보입니다.

목업만 (서버 없이 화면 확인):

```bash
cd web && python3 -m http.server 8600
# http://127.0.0.1:8600/?mock
```

`?mock` 이 붙으면 `api.js` 가 `mock.js` 를 씁니다. ES 모듈을 쓰므로
`index.html` 을 파일로 직접 열면 안 되고 반드시 서버로 띄워야 합니다.
목업에서는 사진 검색(`/api/images`)을 쓸 수 없습니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 뼈대만. 내용은 전부 JS 가 그립니다 |
| `styles.css` | 디자인 토큰(글자 6단계 · 무채색 + 포인트 1색) + 전체 스타일 |
| `art.js` | 카테고리별 상품 실루엣을 SVG 로 그림. 사진이 없을 때 대신 씀 |
| `mock.js` | 서버 흉내. 상품 240개 · 주문 14건, 검색·장바구니·결제·주문 취소/반품·가짜 에이전트 |
| `api.js` | **어댑터.** 화면은 이 파일만 봄. 엔드포인트 목록은 이 파일 머리 주석에 있음 |
| `app.js` | 렌더링과 이벤트 전부 |

## 서버와 맞춰 둔 약속

- **카테고리는 서버가 준다.** `/api/meta` 의 `category_groups` 로 네비를 그립니다.
  `app.js` 의 `GROUPS` 기본값은 서버가 없을 때만 씁니다.
- **색은 variant.** 상품은 `colors: [{color, variant_id, sizes, in_stock}]` 를 갖고,
  장바구니 한 줄의 열쇠는 `(상품, 색, 사이즈)` 입니다 (`lineKey`). 색이 여럿인
  상품은 "바로 담기" 대신 상세로 보냅니다.
- **사이즈 표시 이름은 서버가 준다.** 상품은 `size_options[].label`,
  장바구니·주문 줄은 `size_label` ("ONE_SIZE" → "단일 사이즈", "270" → "270mm").
- **상담 결과는 그리드로 간다.** `/api/chat` 의 `search_results` 를 순위 그대로
  메인 그리드에 그립니다. 채팅 안 카드는 없습니다.
  - `search_product` 결과: 인자를 필터 칩으로 옮기고, 이후 정렬·필터는
    같은 인자로 `/api/products` 를 다시 부릅니다.
  - 사진 검색·비슷한 상품 추천·비교 결과: `/api/products` 로 다시 만들 수 없으므로
    `S.chatPick` 에 고정하고 정렬·필터를 그 목록 안에서만 적용합니다.
    칩의 × 를 누르거나 새로 검색하면 일반 목록으로 돌아갑니다.
- **되돌릴 수 없는 작업은 버튼으로만.** 결제·취소·반품은 `pending` 이 오면 상담창에
  승인 / N번만 / 아니요 버튼을 띄우고, `expires_in` 이 지나면 거둡니다.
  주문 화면의 취소·반품 버튼도 `/api/orders/{id}/action` 으로 같은 확인 대기를 엽니다.
  버튼을 그릴지는 서버가 준 `order.actions` 로만 정합니다.
  장바구니의 "전체 주문"·"선택 항목만 주문" 도 금액 확인 단계를 한 번 거치고,
  그사이 장바구니가 바뀌었으면 결제하지 않고 금액을 다시 보여 줍니다.
- **찜은 서버에 사용자별로 저장한다 (v13 `wishlists`).** 카드·상세의 하트 숫자는 서버가 주는
  `wish_count` = `products.wish_base`(리뷰 수에서 추정한 **합성 시작값**) + 실제 찜 행 수입니다.
  누르면 +1, 해제하면 −1 이 바로 보이도록 숫자를 줄여 쓰지 않습니다(2,359). 같은 사용자가 두 번 눌러도
  한 번만 셉니다. 첫 화면은 추천순이고, 정렬 목록에 "찜 많은순" 이 있습니다.
- **데모 사용자.** 헤더의 "info1 ▾" 에서 `info1`~`info5`(config.DEMO_USERS) 중 하나로 이 브라우저를
  옮깁니다(`/api/switch-user`). 비밀번호 없는 **시연용 사용자 선택**이지 로그인이 아니며, 목록 밖의 id 로는
  옮길 수 없습니다. 같은 메뉴의 "처음부터 다시" 는 지금 사용자만 `/api/reset` 합니다(장바구니·선호 비움,
  주문은 사용자별 처음 상태로, 대화·승인 대기·찜 삭제). 처음 주문은 사용자마다 다릅니다(shopmate.store.db.DEMO_ORDER_PLANS):
  info1 14건(모든 상태) · info2 5건(진행 중) · info3 5건(반품 시연) · info4 3건 · info5 0건, 익명 사용자는 0건.
  데모 사용자끼리는 상품도 겹치지 않습니다. 바꾸거나 초기화하면 페이지를 새로 엽니다. 여러 사람이 같은 데모 사용자를 고르면 데이터가 섞입니다 — 그럴 땐 "새 익명 사용자로 시작".
- **필터 줄.** 분류 · 성별 · **색상 ▾**(25색 팝업, 고르면 같은 조건에 색만 바꿔 다시 검색) 뒤에, 상담·검색에서
  넘어온 조건을 "상담 조건" 이름표 아래 조건마다 칩으로 둡니다. 칩 이름을 누르면 값을 고치고(가격 최소~최대 ·
  사이즈 · 검색어), × 는 그 조건 하나만 풀고, "모두 풀기" 는 전부 풉니다. 브랜드·소재·세탁·재고는 × 로 풀기만.
  무엇을 바꾸든 나머지 조건은 그대로 두고 /api/products 를 다시 부릅니다.
- **헤더 검색은 전체 카탈로그에서 찾는다.** 보던 대분류·소분류는 풀고(성별·색 칩은 유지) 검색어를 나눕니다.
  분류 이름과 정확히 같으면 카테고리 메뉴·칩으로, 브랜드 이름과 정확히 같으면(대소문자·공백 무시)
  브랜드 칩으로 걸고, 그 밖의 글은 서버가 의미 검색(KURE, 상위 50개)으로 찾습니다. 화면이 먼저
  필터로 바꾸므로 위쪽 메뉴·칩이 실제로 걸린 조건과 항상 같습니다. 오타 교정은 하지 않습니다.
- **새로고침해도 이어진다.** 시작할 때 `/api/session` 으로 대화 내역·확인 대기를
  다시 읽습니다. 확인 대기는 서버 세션 DB 에 남아 있으므로, 읽지 않으면 승인 버튼이
  사라진 채 서버가 주문 취소·반품을 막습니다. 찜은 서버 기능이 없어 `localStorage` 에 둡니다.
- **화면 밖의 변경을 따라간다.** 상담(에이전트는 `add_to_cart` 를 승인 없이 바로 실행)·승인
  뒤에는 헤더 숫자와 열린 장바구니·주문 화면을 다시 읽습니다 (`syncShopViews`). 다른 탭에서
  돌아오면(`visibilitychange`·`focus`) 확인 대기도 서버 값으로 맞춥니다.
- **느린 응답이 새 결과를 덮지 않는다.** 의미 검색은 10초 가까이 걸립니다. 그리드 요청마다
  번호를 붙이고 최신이 아닌 응답은 버립니다 (`gridSeq`). 상세도 주소와 다른 응답은 버립니다.
- **실패는 화면에 보인다.** 목록·상세·장바구니·주문을 못 불러오면 이유와 돌아갈 버튼을
  보여 주고, 버튼 처리 중 예외는 토스트로 알립니다. 서버가 보낸 이유 문장(`error`/`message`)을
  그대로 씁니다.

## 화면에 들어간 것

- 스티키 헤더 · 검색 · 카테고리 네비
- 히어로 캐러셀 — 자동 회전 5.2초, 좌우 화살표, 점 인디케이터
- 상품 그리드 — 반응형, 스켈레톤 로딩, 랭킹 뱃지, 찜, 호버 시 바로 담기, 품절 오버레이,
  서버 페이지네이션(60개씩, `X-Total-Count`)
- 상세 — 색 선택 → 그 색의 사이즈별 재고, 품절 표시, 스펙 표
- 장바구니 — **줄마다 체크박스 → "선택 항목만 주문"**
- 주문 내역 — 상태 뱃지 5종, 취소·반품 버튼 또는 안 되는 이유
- 상담 도크 — 사진 첨부, 실행 기록 타임라인, 승인 버튼. 휴대폰 폭(640px 이하)에서는
  화면 전체를 덮습니다. 사진 검색은 실행 기록에 검색 경로(Qwen3-VL 통합 / SigLIP+KURE 대체)와
  사진 이해·검색문·강제 필터·조건으로 쓰지 않은 사진 추정값을 보여 줍니다
- 계획 모드는 서버에서 없어졌습니다(2026-09-28). 응답의 `plan` 은 항상 null 이라 화면도 그리지 않습니다

## 캐시

`server.py` 는 화면 파일에 `Cache-Control: no-cache` 를 붙여 매번 확인하게 합니다
(바뀌지 않았으면 304). `http.server` 로 띄울 때는 이 헤더가 없으니 강력 새로고침을 하세요.
